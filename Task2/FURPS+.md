| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     |              |
| F1  |          На сайте новый клиент видит список доступных депозитов с актуальными ставками                   |              |
| F2  |    Предусмотреть обновление ставок на сайте и в интернет-банке, так как они должны быть актуальными          |     Следует из предыдущего требования         |
| F3  | Клиент может подать заявку на депозит на сайте, оставив свой номер телефона и Ф. И. О                                          |              |
| F4  | Заявка клиента должна отображаться в CRM-системе     |              |
| F5  | 	Клиент должен проходить авторизацию в интернет-банке     |    Это необходимо  перед доступом к персональным ставкам и подачей заявки на депозит        |
| F6  | В интернет-банке клиент видит список доступных депозитов с актуальными ставками и персонализированные ставки лично для него     |              |
| F7  | 	Для каждого депозита должен храниться статус (в работе, согласован, открыт и т.д.) и сотрудник, который его обрабатывает   |     Для прозрачности работы и трекинга         |
| F8  | В интернет-банке клиент может подать заявку на открытие депозита, указав счёт и сумму депозита     |              |
| F9  | Заявка клиента в интернет-банке подтверждается с помощью СМС-кода.     |              |
| F10 |  Заявка должна попасть в АБС для обработки сотрудником бэк-офиса   |              |
| F11 | В интернет-банке данные при передаче надо защитить каким-то механизмом шифрования.     |              |
| F12 | Клиент должен получить СМС-уведомления  уведомления о статусе заявки, а также уведомления после подтверждения размера ставки и открытия депозита     |     Упрощает коммуникацию и снижает нагрузку на кол-центр         |
| F13 | Должна быть реализована отправка статуса обработки заявки клиенту (через СМС или интерфейс)    |              |
| F14 | Сотрудники отдела депозитов и сотрудники отдела кредитов не должны иметь доступа к данным друг друга по требованиям безопасности     |              |
| U   | Удобство использования (Usability) |              |
| U1  | Интерфейс работы должен быть максимально удобным для клиента                          |              |
| U2  | Нужно придерживаться системы дизайна для приложений, которая принята в компании                              |              |
| R   | Надёжность (Reliability)           |              |
| R1  | Все сервисы должны работать 24/7 и быть доступны в 99,9% случаев                             |              |
| R2  | В случае сбоев в ЦОД необходимо, чтобы сервисы интернет-банка были доступны и выдерживали требуемую нагрузку                              |              |
| P   | Производительность (Performance)   |              |
| P1  | Отклик по всем операциям должен быть максимально быстрым и занимать миллисекунды                               |              |
| P2  |  Предусмотреть равномерное горизонтальное масштабирование и распределение запросов между серверами, приложениями и ЦОД                              |              |
| S   | Поддерживаемость (Supportability)  |              |
| S1  | Все модули новой функциональности должны быть покрыты документацией для разработчиков                                |    Для отладки и аудита          |
| S2  | Необходимо предусмотреть логирование действий по обработке заявок  |              |
| +R  | + Ограничения (Restrictions)       |              |
| +R1   | При доработках во всех системах нужно как можно больше использовать технологии, которые уже есть в банке. Например, базы данных MS SQL и Oracle. Можно развернуть новые технологии, но необходимо, чтобы они были совместимы с существующими платформами разработки, и чтобы на них была экспертиза внутри компании.                               |              |
| +R2  | Если нужны очереди сообщений, то лучше использовать Kafka, но потребуются доработки интернет-банка.                              |              |
| +R3  | Стоит подумать о переводе интернет-банка на микросервисную архитектуру, но пока только в рамках задачи открытия депозитов       |              |
| +R4  | При проведении платежей некоторые справочные данные загружаются больше секунды. Нужно продумать, как это исправить     |              |
| +R5  | База данных системы уже перегружена. Онлайн-подача заявок на большое количество продуктов может поставить под угрозу работоспособность банка. Лучше избежать прямой работы интернет-банка с API АБС в новом процессе      |              |
| +R6  | На текущий момент интернет-банк не соответствует требованиям доступности.     |              |
| +R7  | Нужно учитывать, что АБС может масштабироваться только вертикально из-за своей базы данных      |              |
| +R8 | Все взаимодействия между компонентами (сайт, интернет-банк, CRM, АБС) должны быть безопасными и соответствовать внутренней политике информационной безопасности      |     Указано в F требованиях, может сильно повлиять на планирование архитектуры        |
| +R9  | В системе должна быть реализована логика выбора и применения персонализированной ставки на основе профиля клиента    |      Следует из упоминания персонализированных ставок        |
| +R10 | Возможно, функционал хранения и расчета ставок стоит реализовать в АБС, как и весь текущий процесс согласования ставки по заявке.    |        |
| +R11 | Стоит избежать доработки СМС функционала со стороны подрядчика. Реализовать такой бизнес-функционал можно силами команды разработки банка    |              |
